手动功能验证（单进程 `npm run world` 形态，两个隔离 context = 两台设备）：

- 区域切换（服务端权威）：点击“武林大会”→ 服务端校验入口与距离 → `zone-accepted` → 客户端进入展馆；展区翻页器正常（1/5 → 2/5）。目录面板立即打开（阅读层本地），区域状态由服务端裁决。
- 入口校验失败：距离超过 6 米时返回 `zone-rejected` 并提示“暂时过不去：距离入口太远”，客户端保留原区域。
- 断线重连补偿：进入展馆后刷新页面，`welcome.resumed=true` 且 `zone=hall`，客户端恢复到展馆（PRD 15.4）。游客使用 sessionStorage 稳定 id，登录用户使用账号 id。
- 观测端点：`GET /api/world` 返回房间与在线人数（实测 2 人在线）、容量 20。
- “走过去”在 WS 模式下会把建筑入口作为目标提交服务端，权威位置随动。

修复记录：

- WS 消息处理缺少 `zone-accepted`/`zone-rejected`/`peer-zone` 分支（此前的替换静默未命中），导致区域事件丢失。
- `peer-joined`/`peer-left` 在 WS 段误用本地 selfId 而非服务端 id。
- 游客身份每次重连都重新随机，导致位置记忆按失效 id 存取；改为优先采用客户端稳定 id。
- `resumed` 事件的 zone 字段放在顶层而客户端读 `peer.zone`，导致恢复的区域不生效。
- 进入展馆时若等 `zone-accepted` 才开目录，被拒绝时目录永不打开；改为目录立即打开、区域状态单独权威。
