# 性能基线与降级策略

对应 PRD v1.0 第 15 节（性能、可靠性与成本）与 N01/A20。本文记录测量方法、当前基线数值与已实现的自动降级策略；所有数字是本机一次测量结果，不是生产环境承诺。

## 测量方法

- 工具：`npm run bench [秒] [输出]`（scripts/bench.mjs，Playwright + Chrome，1440×900）。
- 流程：导航 → 等待名帖出现（记为首交互时间）→ 在小镇内按 8 个固定地面途经点往返点击移动，每 4 段进出一届展馆 → 最后在页面内用 requestAnimationFrame 连续采样 6 秒帧间隔。
- 指标：首交互毫秒数、帧率 mean/p10/p50（帧间隔换算）、`window.__atomPerf()` 暴露的渲染统计（绘制调用、三角形、像素比、是否已降级）。
- 固定基准：viewport 1440×900、Chrome（headless）、主题“原子江湖”、夜景关闭。更换设备或浏览器版本需重新测量并登记，不能静默替换基准。

## 当前基线（2026-09-22，本机一次测量）

| 指标 | 数值 |
| --- | --- |
| 首交互（名帖可见） | 1.40 s |
| 帧率 mean / p10 / p50 | 60 / 60 / 60 FPS（headless Chrome 上限锁定 60） |
| 绘制调用 | 911 |
| 三角形 | 75,138 |
| 像素比 | 1（headless dpr=1） |
| 页面异常 | 0 |

本机：8 核 Mac（Apple Silicon）、macOS、HeadlessChrome 153。PRD 要求的目标设备（M1/M2 16GB Mac 与中端 Windows 独显机）尚未固定与实测；60 分钟固定路线稳定性、20 人房间压测未做。这些缺口见 docs/VERIFICATION.md 的边界说明。

## 已实现的自动降级

- 触发：连续 3 秒帧率低于 30 FPS。
- 顺序（先保帧率与可读性）：关闭阴影 → 隐藏流萤粒子 → 像素比降到 1。
- 降级后界面在“性能指示器”中标注“已自动降级（阴影/粒子/像素比）”。
- 开关：小镇设置 → “性能指示器”显示实时帧率与降级状态（默认关闭，选择持久化）。
- 降级只影响本地渲染，不删除其他真人或 AI 的服务端/广播角色。

## 观察到的成本大头（后续优化候选）

- 911 次绘制调用主要来自逐建筑、逐树木、逐展位的独立网格；可对重复物件（树木、石块、展位基座、栏杆）做实例化合并。
- 75k 三角形以角色（球体/圆柱组合）和屋顶曲面为主；正式 GLB 资产接入时应带 LOD。
- 首交互 1.40s 含 Vite 开发态模块加载；生产构建（npm run build）下的首交互需另行测量。

## 复现

```bash
npm run dev           # 终端 1
npm run bench 60      # 终端 2：60 秒固定路线
```

输出写入 artifacts/perf-baseline.json（已在 .gitignore 的 artifacts/ 内）。
